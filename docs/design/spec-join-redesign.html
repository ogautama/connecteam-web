Join Us, in the profile’s clothes

Same sixteen questions, same field kit, same 640px column — regrouped into the five cards the Profile page already uses, and submitted with one button at the bottom. The difference from Profile: nothing here is saved yet, so every card is open at once and no card gets its own “Simpan”.

Why the current form feels different

It isn’t worse-designed — it’s an older decision. ApplicationForm still uses the Google-Forms-style kit (QuestionCard, one box per question) that Profile used before Plan 19.

Seventeen cards, one column Sixteen questions each in their own bordered box, stacked — about 3,000px of scrolling before the button comes into view.
No grouping to navigate by KTP number, school city and a bank-book photo all read as equally important. There’s no “I’m nearly done with identity” moment.
Fifteen asterisks All but one field is required, so the asterisk marks the norm rather than the exception and stops carrying information.
Five identical dropzones Each upload is a full-width dashed box saying “Pilih file”. You can’t see at a glance how many are still outstanding.
A six-name radio list Pengundang / Unit is the live leader list — it grows. As a radio stack it’s the tallest card on the page and grows with the team.
Errors arrive one at a time Submit surfaces only the first problem, as a line of text above the button, with no link back to the field it’s about.

  1. The header earns its gradient bar Same card as today, plus what the form is going to cost you: four sections, five minutes, and the required rule stated once instead of fifteen asterisks.
  2. Nama & kontak — the Profile identity header, before there’s an identity Same three fields the Profile header edits. Email is a normal input here (no Google account to lock it to yet) and carries the one line explaining why we ask.
  3. Identitas — the same two-column grid EditField + EditInput exactly as IntakeSummary uses them: label above input, address spans both columns. Nothing new to build.
  4. Pendidikan — jenjang becomes a select The four-option radio stack collapses into the same EditSelect Profile already edits it with, freeing the row for tahun kelulusan.
  5. Dokumen — five tiles and a counter The Profile’s DocTile in its empty state: dashed navy for the four required, dashed grey “Opsional” for the spouse ID. The “0 dari 4 wajib” chip ticks up as files are picked — one glance instead of five dropzones to scan.
  6. Pengundang, then the only button on the page The last question and the action share a card, so “what’s left” and “done” are the same stopping point. One Kirim aplikasi — no per-card Simpan, since nothing exists to save into yet.

One list, three screens

EDUCATION_OPTIONS in src/lib/memberIntakeOptions.ts is the only definition — the Join form, the Profile editor, and ApplicantQueue’s label lookup all read it. Adding a row there covers all three.

But it’s a Prisma enum, not a string

education is EducationLevel in schema.prisma, so this needs a real migration — ALTER TYPE … ADD VALUE 'diploma'. Cheap and additive (nothing stored changes), but it’s a schema change, not a content edit. Enum position doesn’t matter: display order is the array’s.

Label wording — decided

Diploma (D1–D4), so applicants at any diploma level recognise their option without guessing. Worth noting the source Google Form didn’t offer Diploma at all — this is a deliberate addition, not a transcription fix.

What this costs to build

Mostly a re-layout of ApplicationForm.tsx. Nothing in the data model, the server action, or Storage changes.

Already exists

  • Every card and input. FieldGroupCard, EditField, EditInput, EditTextArea, EditSelect and DocTile are all exported from IntakeFormFields.tsx and already shared by both forms.
  • Submit stays as it is. Same handleSubmit: check the email, upload five files, call submitApplication. One button in, one button out.

New, and small

  • An empty/picked state for DocTile. It currently takes a saved url; here it needs a pending File — filename in place of “Terupload”, plus “Hapus”.
  • Per-field validation. Today’s check returns the first error as a string. Grouped errors mean a Record<field, string> and a scroll-to-first — worth it, but it’s the real work in this change.
  • An EditSelect for Pengundang / Unit. The existing one is hardcoded to EDUCATION_OPTIONS; it needs to take options as a prop.

Open questions

  • Should the button stick? Mocked at the end, as asked. On mobile a sticky bottom bar keeps it reachable — but it also covers content on a form this long. Easy to add later either way.
  • Radios or a select for Pengundang? A select scales with the leader list; radios show every name without a tap. Six names today.
  • Does the member “Isi Data” first-fill form follow? JoinDataForm’s pre-save branch is the same question-card stack. Matching it here leaves that one the odd path out — worth doing in the same pass.
