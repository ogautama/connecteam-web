Filling the download-pruforce placeholder: one official download link, two very different install paths

Content proposal for the first item of the Onboarding checklist in Plan 07's quest hub, sourced per Plan 11 (which moved PRUForce out of Official Systems and into Onboarding). Today the item renders <PlaceholderDetail tag="Segera hadir" note="Dipindah dari Plan 11." /> — see src/app/member/onboarding/QuestHub.tsx. Mockup only, nothing built yet.

🔗 The download link, verified 2026-08-05 and publicly reachable without login: https://portals.prudential.co.id/agent/application/view/68105c1e152990ce5bc2e7a6 — Prudential Indonesia's own agent portal page for PRUForce 2.0, carrying both "Unduh untuk iOS" and "Unduh untuk Android". This is the same URL Plan 11 recorded, now confirmed live. Prudential's own Digital Services broadcast shortens it to http://bit.ly/PRUForce2, which currently 302s to exactly that page. The full app list lives one level up at /agent/application/download.
🚫 There is no app-store link to give. Don't add one. Checked 2026-08-05: the Indonesian App Store has no PRUForce — PT Prudential Life Assurance's developer page lists only PRUFast Mobile and PRUWorks, and the old apps.apple.com/id/app/pruforce-mobile/id1082618139 now 404s. Google Play Indonesia has no PRUForce either; the vn.com.prudential.pruforce.dev listing that search engines surface is Prudential Vietnam's app, not ours. Indonesian PRUForce ships exclusively through the agent portal, side-loaded.
⏳ Never hardcode the Android APK URL. The "Unduh untuk Android" button points at a signed Google Cloud Storage object with X-Goog-Expires=604800 — it dies after 7 days, and the path is regenerated per upload (it even embeds the uploading Prudential staffer's email). The iOS button is an enterprise OTA manifest, itms-services://?action=download-manifest&url=…/app.plist, which no browser other than mobile Safari will act on. Both are reasons the content module should link the portal page and let Prudential's own buttons do the work.
❓ Two things this mockup deliberately does not invent. (1) The per-OS install steps below were drafted as inferences from the link types above (APK sideload; Safari + trust profile) and shipped with a visible perlu konfirmasi caveat. The content owner confirmed them on 2026-08-05 ("sudah betul caranya") and the caveat came off — they're checked now, not guesses. Plan 11 still records more iOS-popup troubleshooting copy on the gated Google Sites page; that would extend these, not correct them. (2) "Cara Mengikuti Kelas My First Case (MFC)" also belongs to Onboarding per Plan 11, but it is its own step, not part of this one, and its content is still behind the same gate — consistent with project_member_content_source_gated.

  • PRUDigitalfriend — WhatsApp +62-811-1566-512 (ketik: DF), prudigitalfriend@prudential.co.id, the helpdesk for PRUForce / PRUFast / PULSE / PRUWorks → Yellow Pages too.
